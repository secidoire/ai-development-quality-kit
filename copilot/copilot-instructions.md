# Copilot Repository Instructions案

- 既存の顧客テンプレート、設計書、Figma、API仕様、バックエンド実装、テスト資産を尊重し、未確認の期待値を補完しない。
- 顧客向け基本設計に書く外部挙動と、共通部品/画面/カスタムフック/APIの責任境界を分けて考える。
- API/IFは案件ごとに正本候補を確認し、設計書、API仕様、抽出結果、実装観測を照合する。観測された挙動と承認済み要求を分け、追えない箇所は未確認にする。
- テストはVitest、Storybook Interaction、Playwrightの役割を分け、全層で同じ項目を重複検証しない。
- トレースIDやcoverage%だけで設計充足を保証したと扱わない。候補リンク、承認済リンク、未確認事項を明示する。
