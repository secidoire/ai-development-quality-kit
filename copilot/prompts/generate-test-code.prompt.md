# テストコード生成プロンプト

承認済みまたは社内合意済みの検証条件からテストコードを作成してください。

前提:

- Next.js。
- カスタムフックや純粋ロジックはVitest。
- 画面状態や共通部品との組み合わせはStorybook Interaction。
- 主要導線や画面遷移/API連携はPlaywright。

出力:

- 作成/変更ファイル。
- テストID。
- 対応する設計項目ID。
- 期待値の根拠。
- 実行方法。
- 実行していない場合は、未実行と明記。

品質基準:

- まず現実の使われ方、ユーザー操作、期待挙動を検証する。
- 次に境界値、異常、状態、未検証分岐を補う。
- coverage%は不足診断として使い、coverage達成だけを目的にしない。
- API spyやmockは、payload、送信抑止、結果反映など意味のある契約や挙動をassertする場合は使ってよい。
- screenと実hookを組み合わせた統合寄りテストも、既存構成に合う場合は候補にする。

禁止:

- 未確認仕様を勝手に期待値へする。
- OpenAPIや抽出結果だけを根拠にせず、合意済みのAPI/IF正本または実装観測と照合する。追えない箇所は未確認にする。
- 実行していないテスト結果をpassと書く。
- coverageを上げるだけの低価値テストを量産する。
- mockが呼ばれたことだけを根拠に、契約や結果を保証したと扱う。
