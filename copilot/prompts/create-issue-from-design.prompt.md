# 設計からIssue分解プロンプト

許可された設計書Markdown、Excelテスト仕様、既存テスト、API/OpenAPI/バックエンド実装情報から、Issue草案を作ってください。

Issueに含める項目:

- 設計出典/版/位置。
- ユーザーの使われ方、操作、期待挙動。
- 範囲/非対象。
- 依存/契約: Figma、OpenAPI、バックエンド実装、共通部品、画面、カスタムフック。
- 受入条件。
- 適切なテスト層: Vitest、Storybook Interaction、Playwright。
- 未解決事項。
- 完了証拠: テスト、実行結果、レビュー、トレース更新。

制約:

- 設計に無い受入条件は確定せず、提案または質問で止める。
- Issueを細かくしすぎて、ユースケース端から端の責任を失わない。
- GitHub上coding agentへ自動PRを作らせる前提にしない。
- 実際のIssue起票は、案件権限と運用承認がある場合だけ行う。
