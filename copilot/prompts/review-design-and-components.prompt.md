# 設計書レビュー・部品分割プロンプト

許可されたMarkdown設計書、Figma情報、OpenAPI/バックエンド実装、既存コード、Storybook、テストを読み、設計書レビューと部品分割方針を出してください。

出力:

- 参照したrepo/path/commit/設計版。
- 抜け漏れ: 入力、表示/活性、遷移、API、通信失敗、権限、状態、非同期、空/境界値。
- 矛盾: 設計書、Figma、OpenAPI/バックエンド実装、既存実装、既存テストの不一致。
- テスト可能性: 期待結果、前提データ、到達手順、観測点、責任境界。
- 共通部品/画面/hook/APIの責任分界候補。
- コンポーネント分割方針: 既存再利用、変更影響、移行コスト、未確認事項。
- 顧客確認事項と社内設計判断事項。

制約:

- docs repoとcode repoが兄弟配置でも、repoごとの権限とcommitを分ける。
- 読めることと変更できることを混同しない。
- 二つのrepoへ勝手に一括commitしない。
- 親フォルダを開けば全指示が自動で正しく効くとは保証しない。
